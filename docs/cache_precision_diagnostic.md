# 缓存一致性精度诊断（Colab A100，2026-09-18）

四张定向诊断图像中，FP32 消除了 cached/uncached 的 token 差异；仅提升输出头精度没有消除 BF16 的两处 A/B 翻转。这是小样本上的工程规避证据，具体层或算子的原因尚未定位。

## 设计

保留首轮两张失败图像 `scene_00000_nuisance`、`scene_00001_base`，另取两张通过图像 `scene_00000_base`、`scene_00002_base`。四种模式分别重新加载固定 checkpoint；每张图执行 cached、cached repeat、uncached 三次 greedy generation。记录每步前缀 token、top-5 和 A/B logits，避免跨不同前缀解释差值。关闭 TF32，启用确定性算法；没有放宽 E0 的逐 token 一致性要求。

| 模式 | token 不一致 | A/B 不一致 | cached 重复不一致 |
|---|---:|---:|---:|
| BF16 | 2/4 | 2/4 | 0/4 |
| BF16 主体 + FP32 输出头 | 2/4 | 2/4 | 0/4 |
| FP16 | 4/4 | 0/4 | 0/4 |
| FP32 | 0/4 | 0/4 | 0/4 |

FP16 的差异均为答案标签之后是否带句号，不能计为 A/B 翻转。诊断样本有意包含失败案例，上表不能估计一般失败率。

## 同一答案前缀的证据

首轮 nuisance 失败图像的 BF16 `logit(A)-logit(B)` 为 cached −0.375、uncached 0；base 失败图像为 −0.125、+0.125。输出头改为 FP32 后，分别仍为 −0.35541153/+0.03059196 与 −0.13270950/+0.20498657。

完整 FP32 下，两张图像分别为 +0.03961563/+0.03966713 与 +0.09181595/+0.09186172：差值仍非完全相同，但不再改变本次选择。另两张诊断图像也通过 token 一致性检查。

结果支持精度相关的推理敏感性，不能把原因限定为最后输出头的舍入。不同加载精度同时改变参数表示与计算精度，本诊断没有将两者完全分离，也没有证明任意图像的缓存状态或逐层 hidden states 完全相同。
